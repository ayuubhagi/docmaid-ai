# Deploying DocMaid

Production runs on three free tiers:

- Backend: a Docker web service on Render, built from `backend/Dockerfile`.
- Frontend: the Vite build on Vercel, at https://docmaid-ai.vercel.app.
- Database: Postgres on Neon.

Render and Vercel both deploy when `main` changes.

## Render (backend)

The container runs `alembic upgrade head` before starting uvicorn, so migrations apply on every deploy.

Environment variables, set in the Render dashboard:

| Variable | Value |
|---|---|
| `ENVIRONMENT` | `production` (the app refuses to start if `SECRET_KEY` is still the dev default) |
| `SECRET_KEY` | long random string, generated by Render |
| `DATABASE_URL` | Neon connection string, starting with `postgresql+psycopg2://` |
| `CORS_ORIGINS` | `https://docmaid-ai.vercel.app,https://documind-ai-hazel-theta.vercel.app` |
| `FRONTEND_URL` | `https://docmaid-ai.vercel.app` |
| `LLM_PROVIDER` | `groq` |
| `GROQ_API_KEY` | from https://console.groq.com |
| `GROQ_MODEL` | a model Groq currently serves |
| `UPLOAD_DIR` | `/tmp/uploads` |
| `CHROMA_PERSIST_DIR` | `/tmp/chroma_data` |

Health check path: `/health`.

Three of these have bitten me:

- `DATABASE_URL` needs the `+psycopg2` part. SQLAlchemy 2.1 maps plain `postgresql://` to psycopg 3, which isn't installed, and the backend crashed on boot on Sept 29 until I added it.
- `GROQ_MODEL` has to be set. The code default, `llama-3.3-70b-versatile`, was retired for free accounts on Aug 16, and every chat request returned a 404 until I changed it.
- `CORS_ORIGINS` must list the current Vercel domain. When the frontend moved to `docmaid-ai.vercel.app`, the old value blocked every request.

`render.yaml` has the right `CORS_ORIGINS`, but still has the old service name, the old `FRONTEND_URL` and `LLM_PROVIDER=demo`. The dashboard values above are what is live. Don't sync the Blueprint until `render.yaml` matches them.

## Vercel (frontend)

- Root directory: `frontend`
- `VITE_API_URL`: the backend's `onrender.com` URL

`VITE_API_URL` is read at build time, so changing it needs a redeploy. `vercel.json` rewrites every path to `index.html` so client-side routes survive a refresh.

## Neon (database)

Before anything risky (a migration, a backfill), create a branch from `production` in the Neon console. It's an instant copy and it's my data rollback.

## Rolling back

- Backend: Render dashboard, Events, pick the last good deploy, Rollback.
- Frontend: Vercel dashboard, Deployments, pick the last good one, Promote to Production.
- Data: point `DATABASE_URL` at the Neon backup branch.

Rolling back the backend doesn't undo a migration. The older image will fail on startup if the database is at a revision it doesn't know, so downgrade with Alembic first or restore from the Neon branch.

## Free tier limits

- The backend sleeps after 15 idle minutes. The next request takes about a minute.
- Disk is ephemeral. Accounts, conversations and chunk text live in Neon. The Chroma vector index is rebuilt from stored chunks on the first question after a restart.
- Uploaded files sit in `/tmp` and are lost on restart. Only the extracted text survives.
- The embedding model (about 79 MB) downloads on every cold start, which adds 15 to 20 seconds to the first upload or question.
- Rate limits are kept in memory, so they reset on restart. That's fine for one process.
- Stripe isn't configured in production, so the Pro button on the pricing page says "Coming soon".
